# SP-Game — игровой сервер

PHP, Swoole WebSocket, Repository → Service → Core. Рабочие игровые данные
находятся в Swoole Tables и периодически сохраняются в MySQL. Точка входа:
`src/main.php`. Контейнер разработки: `swoole_app`.

## Версия до подключения кабинета

Контрольная метка: **`pre-cabinet-2026-11-03`**.
Резервная ветка: `backup/pre-cabinet-2026-11-03`.

Резервная ветка и метка публикуются отдельным корневым коммитом, без прежней
истории приватных конфигураций. Существующая удалённая `main` не переписывается;
для получения этого снимка использовать именно указанную метку.

Это исходники работающего сервера с прежней регистрацией/авторизацией через
игровой WebSocket. Сервис `/opt/sp-game.cabinet` для этой версии не требуется.
Клиент той же контрольной версии:
[sp-game-client-js / pre-cabinet-2026-11-03](https://github.com/SNAK84/sp-game-client-js/tree/pre-cabinet-2026-11-03),
коммит клиента `c76fcec3bc124827f6e5599012dd8f40a38fc1bc`.

Снимок включает исходники, composer.lock, конфигурацию сборки, миграционные
скрипты, документацию и проверки. Не включает приватный `.env`, его архивные
копии, core dumps, логи, vendor, состояние MySQL и секреты тестовых аккаунтов.
Локальные конфигурационные файлы при публикации не удаляются и не меняются.

## Получение исходной версии

Развернуть в новый каталог, не затирая текущий сервер:

```bash
git clone --branch pre-cabinet-2026-11-03 --single-branch \
  https://github.com/SNAK84/sp-game-server.git \
  /opt/sp-game-before-cabinet
cd /opt/sp-game-before-cabinet
git describe --tags --exact-match
```

Для запуска нужны отдельно сохранённый приватный `.env`, совместимая MySQL
и PHP/Swoole runtime. Имена параметров показаны в `.env.example`; реальные
пароли в Git не хранятся. PHP-зависимости восстанавливаются из composer.lock:

```bash
composer install --no-interaction --prefer-dist
```

На момент снимка работающий контейнер использует **PHP 8.2.33 / Swoole 5.1.6**.
Исторический Dockerfile устанавливает OpenSwoole без фиксации версии: его
новая сборка не считается проверенным воспроизведением текущего runtime.
Для отката кода использовать сохранённый рабочий runtime; перенос игры
на общий PHP 8.4-образ кабинета выполняется отдельным этапом.

## Безопасный откат

- GitHub хранит код, не резервную копию игровых данных. Сохранить отдельно
  приватный `.env`, БД и текущую версию кода до переключения.
- Не запускать второй `src/main.php` на той же игровой БД. Он не является
  безопасной проверкой восстановления и может конкурировать с основным миром.
- Перед заменой исходников штатно остановить основной процесс, дать ему
  завершить сохранение, затем применять согласованный код и запускать его
  единственным игровым процессом.
- Для управления текущим контейнером используется `swoole_manager.sh`;
  `stop` и `restart` дают процессу до 60 секунд. Не использовать очистку логов.
- Не выполнять `down -v`, reset игровых таблиц, переинициализацию мира или
  массовый запуск `migrations/*` ради отката исходников. Многие скрипты
  миграций предназначены для одноразовых QA-сцен и меняют игровые данные.
- После запуска проверить свежие логи, соединение клиента, очереди и флоты.
  Само клонирование кода не выполняет эти проверки работающего мира.

## Проверки кода

```bash
find src tests migrations -type f -name '*.php' -print0 | xargs -0 -n1 php -l
vendor/bin/phpstan analyse --memory-limit=1G
```

Тестовые сценарии и их границы: [tests/README.md](tests/README.md).
Полный набор игровых/E2E-проверок не запускается автоматически при получении
снимка. Сохранение копии не требует остановки или перезапуска основного сервера.

## Важное ограничение безопасности истории

Исключение приватных файлов из нового снимка не удаляет конфиденциальные
данные, попавшие в старые ветки ранее. Раскрытые credentials нужно отозвать/
сменить; очистка прежней истории — отдельная согласованная операция.
Клонирование этой метки с `--single-branch` не получает прежнюю историю.
