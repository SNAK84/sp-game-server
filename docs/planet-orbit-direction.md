# B018: направление орбиты новой планеты

01.11.2026. Изменена одна исполняемая строка одного production-файла:
из `GalaxyGenerator::CreatePlanet()` удалена перезапись rotation через rand.

## Причина и исправление

CreatePlanet получает Galaxy.rotation → передаёт его в generatePlanet →
получает правильный planet.rotation → раньше заменял его случайным → сохранял.
При несовпадении новая домашняя планета двигалась против направления системы.
FleetColonizationService уже сохранял направление generatePlanet без замены.

Теперь оба пути сохраняют направление системы. Колонизацию не переводили на
CreatePlanet: проверки орбиты, commit зависимых строк, колонизатор, груз и
локальная компенсация остаются в существующем сервисе миссии.
Формулы расстояний/скорости/температуры/полей, имена, API, схема БД и лунный
путь не менялись. Массовая корректировка старых планет не добавлялась.

Существующий startup `reconcilePlanetOrbits()` уже выравнивал направления.
Поэтому положительная проверка только после restart недостаточна: обе новые
планеты проверены **до следующего restart**, затем повторно после него.

## Отдельная находка и границы

После первого reload направление совпало в raw WS/SQL/canvas, но проверка
движения обнаружила **B043**: обновление той же системы во время начального
zoom оставляет устаревший zoomAnimationFrameId, и основной animation loop
перестаёт рисовать. За3 секунды координаты маркера не изменились, хотя server
time и RAF росли; JS errors0. Клиент в B018 не исправлялся.

Для повторной проверки направления тест ждёт завершения начального zoom,
а не вызывает animate()/cancelZoomAnimation() вручную. Это не устранение B043.

Живая сцена проверяет направление1. В систему с направлением0 ради проверки
не вмешивались; системные направления и существующие орбиты не перегенерировали.
Синтаксис трёх PHP-файлов (`php -l`), Python (`py_compile`), собственный diff
от backup и whitespace проверены отдельно от runtime.
Изолированный CelestialNamesIntegrationTest не запускался по принятому режиму
работы; его проверки направления актуализированы, старый физический JSON не
перезаписан. Один legacy RNG-отсчёт пропускается только внутри этого теста,
чтобы сохранить прежнюю последовательность несвязанных физических эталонов.
