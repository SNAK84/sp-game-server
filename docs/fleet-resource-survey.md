## Время и топливо

S — сенсоры, N — геологоразведчики, D — сложность объекта:

```text
P = 10 + 5*S + 10*log2(N)
delta_q = min(1-q, P/D)
T = ceil(max(300, 1800*(D/60)/(1 + 0.05*S + 0.25*log2(N))))
```

Параметры фиксируются при фактическом начале. Один активный проход на
игрока/объект; другие игроки и другие сектора независимы. Отзыв и нехватка
топлива не дают частичного результата. После заправки/Resume проход
начинается заново. Расход — существующая ставка удержания **всего** флота
0.1 × базовый расход/час; бак в UI уменьшается от hold.lastAt/rate.
Расчёт обычной отправки включает полёт туда, работу и возвращение.
Расчёт маршрута также прибавляет работу к расходу каждого этапа.

## Знание и сохранение

`ResourceSurveys` хранит личные q, K, дату и снимок. Общие запасы остаются в
`OrbitalResourceSites`. `stock()` лениво проецирует естественное пополнение
G до C; обследование не пишет ни физический запас, ни груз/ресурсы планеты.
Сначала восстанавливается K по старому q, затем добавляется delta_q × G.
При q=1 повтор не добавляет новый резерв сверх естественного прироста.
Galaxy отдаёт только личный датированный снимок, не чужие знания и не
текущее состояние после чужой добычи. Через24ч снимок помечается устаревшим.

`SurveyResults` — receipt по случайному UUID прохода, а не ID команды:
числовые ID очищенных команд могут повторяться после restart. Перед
эффектами сохраняется точный after знания и ID доклада; retry использует
тот же результат. Перед восстановлением проверяется принадлежность
зарезервированных ID: если после crash ID получил другой объект/доклад,
receipt перепривязывается без перезаписи чужих данных. Сначала durable
checkpoint, затем знание/сообщение, applied receipt, затем окончание команды.
SQL-транзакция и новый saver не вводятся. Нужная запись проверяется после
Table::set/update и sync; при ошибке SQL команда остаётся due для retry.
Во время применения результата отзыв/правка/передача/вступление в бой
блокируются. Это локальная защита обследования, не общая транзакционная
архитектура всех Fleet.

Внешние эффекты старта вынесены из commit отправки/правки плана: RESEARCH
сначала получает отдельное due-событие существующего EventLoop.
Один доклад обычной Messages/ActualData-цепочкой, затем обычное сообщение
возвращения. Временное изображение корпуса — существующий colonizer.gif.
Объектные иконки гиганта/пояса берутся из types.png: кадры5/6, те же
CSS-mask, размеры и подсветка, что у планеты/луны/обломков.

## Ограничения и риски

- Results ограничен4096 receipts, Knowledge8192 строками. Retention ещё
  не внедрён: нельзя удалять checkpoint, пока возможен replay команды.
  Переполнение должно останавливать выдачу, не терять результат молча.
- Компенсация runtime может отказать; общий B006 (индексы при set(false))
  не исправляется этим этапом. Глобальной crash-атомарности всех Fleet,
  команд, трюма и MySQL repositories этот механизм не обещает.
- Отдельный межпроцессный lock не введён; используется существующий
  scheduler. Реально конкурентные независимые writers требуют отдельного
  аудита, а не утверждения «гонки невозможны».
- Воспроизведённые посторонние проблемы: B001 (очистка новой страницы
  старым Hide; reload восстанавливает), T003 (временный DNS Chrome),
  B009 (Accounts/uniq_token). Записаны в found-bugs, не исправлялись здесь.
  Для финальной проверки временно закреплялись только два игровых домена
  в hosts тестового браузера. Эта строка удалена после проверки; DNS игры
  и её контейнеров не менялся. Вкладка QA закрыта, исходная snak1 оставлена
  на странице флотов, подключение открыто; mobile emulation выключена.
- Для этапа5 физический запас надо получать через ленивую проекцию G,
  а не читать устаревший *_stock как готовый актуальный баланс.
