## Правила, подтверждённые пользователем

- Потерян контакт — по умолчанию лететь к последней рассчитанной точке встречи.
  Если там нет доступной цели, остановиться с сообщением. Игроку нужно дать
  альтернативу «остановиться при потере контакта» с некоторого уровня технологии.
  Позднее пользователь утвердил порог: **Компьютерная технология 6**;
  он реализован в 3Б.1б.
- До начала боя разрешён отзыв; во время боя оба флота остановлены.
- Подкрепления тех же владельцев — со следующего ещё не рассчитываемого раунда.
  Третий игрок не становится союзником автоматически.
- Атакующий продолжает маршрут, по умолчанию — домой. Выживший защитник ждёт
  команды на продолжение своего маршрута.
- Обломки — в свободной точке боя по действующему проценту. При уничтожении
  противника победитель берёт до 50% оставшегося груза в пределах вместимости.
  Топливо из бака не захватывается.

Это правила последующей реализации боя; подготовка не списывает потери/груз.

## Read-only аудит до изменений

- `FleetRendezvousService::target()` авторизует собственные/входящие флоты для
  доставки. `meeting()` читает живую траекторию. Просто разрешить там сенсорные
  контакты нельзя: это откроет live-прогноз через обычный transport/preview.
- Мобильный скан сохранял точку/курс, а фаланга — логические endpoints/ETA;
  отдельного физического снимка для расчёта перехвата не было.
- `FleetMissionService` не выдаёт ATTACK для FLEET. Наличие `fleet` в enum
  миссии само по себе ничего не запускает. Подменять им транспорт нельзя.
- Активация MOVE к FLEET использует live-rendezvous доставки, а ATTACK уходит
  в `FleetAttackService::arrive()`, который требует настоящую планету/луну.
- `FleetBattleService` и `PlanetBattles` координируют раунды по planetId,
  блокируя планету и участников. Чистый `FleetCombatService` и TaskWorker
  переиспользуемы; привязывать пространственный бой к вымышленной планете нельзя.
- `DebrisFields` имеет ключ galaxy/system/orbit; POINT-обломков пока нет.
  Нельзя незаметно положить добычу на ближайшую планету/фиктивную орбиту.
- `BattleReportService` уже поддерживает `mission.spaceTarget` без планеты
  (для экспедиций); новый формат публичного боевого доклада не требуется.

## Реализовано

`FleetInterceptionService` — локальный сервис подготовки, без нового WS action.

1. Фаланга/сенсор при настоящем скане сохраняют приватный `_observation`:
   время, POINT, текущий наблюдаемый участок, fingerprint траектории.
2. Мобильный MOVE прогнозируется по измеренному вектору скорости. Тайные
   конечная точка и время прибытия **не сохраняются в его модели**: две разные
   скрытые цели при той же наблюдаемой скорости дают одинаковый прогноз.
   Курс ограничен только известной внешней геометрией системы (экспедиционной
   орбитой); неизвестный поворот/остановка у тайной цели не предсказываются.
   Фаланга/входящая видимость уже раскрывают участок и ETA, поэтому их модель
   может фиксировать его физический конец. Орбитальная стоянка прогнозируется
   по сохранённой угловой скорости из существующего физического resolver.
   После **известного наблюдателю** конца участка/удержания остаётся последняя
   точка; будущие команды не читаются.
3. `observation()` проверяет владельца, freshness источника, текущую фазу и
   fingerprint. Входящий к игроку флот использует существующую видимость.
   Сам ID не даёт права получить цель; разрешение доставки не расширено.
4. `positionAt()` и `meeting()` после получения снимка не читают цель, её команды
   или планету. Смена курса/потеря источника не меняют уже рассчитанную встречу.
   Обновление возможно только новым реальным наблюдением.
5. Формулы расстояния/времени прежние. Поиск встречи ограничен, учитывает
   существующее округление времени до секунд и не назначает прилёт раньше
   рассчитанного той же формулой. Другая система отклоняется.

Физический снимок — **не разрешение начать бой**. В 3Б.1 исполнитель обязан
повторно проверить доступность цели и фактическую встречу в точке/времени.

Мобильные DTO очищаются в `FleetSensorService::contacts()`, фаланга — в
`PhalanxScans::get()`. Конечная точка, время и fingerprint мобильного контакта
не уходят в Page/ActualData ни на одном tier. Клиентский `lastKnownPosition`
не вводился. Старые снимки без движения не становятся live-разрешением:
нужен следующий настоящий скан.

Для сенсора действуют прежние 30 секунд свежести/5 минут последней отметки.
Фаланга не сканирует пассивно: используется только её последний оплаченный
буфер с прежним сроком хранения, и только пока не сменился наблюдаемый участок.
Хранение снимка не даёт права скрыто следить за новым положением.

Буферы остались по 16 KiB. Приватная и публичная части записываются вместе;
у фаланги упаковка по-прежнему происходит до оплаты. Переполнение не приводит
к усечению траектории, повторной оплате или подмене старого результата.
