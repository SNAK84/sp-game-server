## Подтверждено узким аудитом

- `FleetControlService::startHold()/settleHold()` уже обслуживают OBSERVE:
  расход из бака, время исчерпания, переход в пассивную остановку. Наличие
  OBSERVE само по себе не включает сенсоры, в том числе после ручного Stop.
- `FleetRendezvousService::target()/targets()` разрешают свои и входящие
  флоты. EXPEDITION и базирующиеся флоты исключены. По известному ID нельзя
  разрешать новый живой доступ без отдельной серверной проверки контакта.
- Обзор и галактика используют `FleetsPage::buildVisibleFlyingFleetList()`;
  список целей отправки — `FleetRendezvousService::targets()`. Проекция
  входящих содержит сведения о маршруте, поэтому её нельзя целиком выдавать
  для контакта, раскрывающего только точку обнаружения.
- `EventLoop` имеет существующий ActualData; отдельный WebSocket-канал,
  клиентский polling и новый протокол ACK не требуются.
- Используется готовая технология `135/sensor_tech`.
  Новая технология для разведчика не нужна. `136/extraterrestrial_mining_tech`
  подключается к обследованию/добыче своими этапами.
- Read-only проверены параметры кораблей в текущей БД. Согласованная цена
  разведчика равна базовой цене колонизатора; это не дешёвый аналог зонда.
  Назначен новый ID 221 / sensor_scout; удалённый ID 220 Сборщика не переиспользован.

## Сенсорный разведчик

| Параметр | Значение |
| --- | --- |
| Цена | 10 000 металла / 20 000 кристалла / 10 000 дейтерия |
| Базовая скорость | 10 000, импульсный двигатель |
| Вместимость, включая топливо | 1 000 |
| Базовый расход | 50 |
| Атака / щит | 5 / 50 |
| Требования | Верфь 6, Сенсорные технологии 3, шпионаж 5, импульсный двигатель 4 |

Работает только в системе фактического нахождения флота и только после явного
включения сенсорного режима при активном удержании. Перелёт, обычный OBSERVE
или ручная остановка автоматически сканирование не включают.

Уточнение свободных целей и исправление запаса топлива от 23.10.2026:
[`fleet-point-bounds.md`](fleet-point-bounds.md). Новая POINT-цель выбирается
между min_distance системы и её орбитой перехода; запас OBSERVE может превышать
расчётный расход перелёта, в пределах вместимости и запасов дейтерия.

Оплата: используется существующий расход удержания всего
флота — `FleetHoldFuelPerHourFactor`, сейчас 0.1 базового расхода в час.
Дополнительной платы за каждый скан нет. Один разведчик без сопровождения:
5 дейтерия/час удержания при неизменном базовом расходе. Топливо самого
перелёта считается отдельно обычным движком. При исчерпании бака сканирование
прекращается; флот остаётся пассивно остановленным, без автоматической дозаправки.

## Формула обнаружения

```text
score = 2 × (S − E) + floor(log2(N)) + floor(log2(T)) + M
```

- S — завершённый уровень Сенсорных технологий наблюдателя.
- E — завершённый уровень шпионской технологии владельца цели.
- N — число Сенсорных разведчиков в одном активном источнике, N ≥ 1.
- T — суммарное количество кораблей цели, T ≥ 1.
- M = 2 при активном внутрисистемном MOVE, иначе 0.

| score | Сведения |
| --- | --- |
| <0 | Контакт не обновляется |
| 0–3 | Положение, курс движущейся цели и время наблюдения; без владельца и состава |
| 4–7 | Дополнительно владелец и диапазон численности: 1–9, 10–99 и т. д. |
| ≥8 | Дополнительно точные количества по типам, текущий внутрисистемный участок и движение маркера |

Груз, бак, XP и будущие команды не раскрываются ни на одном уровне. На3А.2
при score>=8 доступен конец только текущего MOVE, не конечная цель всей миссии;
временные опоры служат интерполяции, отдельный таймер в карточку не добавляется.
Пример: S=3, E=3, N=1, T=100:
движущийся флот даёт score=8, остановленный — 6. При E=5 эти значения
снижаются до 4 и 2. Удвоение N добавляет один балл, а не удваивает мощность.

Для нескольких источников одного наблюдателя выбирать лучший действительный
результат, не складывать баллы отдельных флотов. Это предотвращает усиление
за счёт дробления одинакового числа разведчиков на множество источников.
Вычисление по количествам групп, без цикла на каждый корабль.

## Жизненный цикл контакта

- Скан раз в 10 секунд. Свежесть снимка — 30 секунд. Последняя отметка
  доступна до 5 минут с момента наблюдения, явно помечена как устаревшая.
- Пока контакт живёт, новый запрос не должен незаметно подменять снимок
  настоящими координатами или раскрывать скрытый маршрут через preview.
- Уход/бой/потеря источника, выключение режима или отсутствие топлива
  прекращают новые сканы. Без другого действительного источника нельзя
  продлевать право сопровождения, даже если старая отметка ещё хранится.
- Базирующиеся флоты, межсистемные/межгалактические переходы и сама фаза
  EXPEDITION не обнаруживаются. Вход в скрытую фазу немедленно запрещает
  живой доступ независимо от TTL; остаётся только ранее известная отметка.
- Снимок контакта отделён от собственного/входящего live fleet DTO и снимка
  фаланги. Существующие права видимости не урезаются и не получают дублей.
- Галактика, обзор и выбор целей получают только разрешённый уровень сведений
  через обычный ActualData. Боевая отправка «Перехват» остаётся этапом 3Б.
- Временные контакты хранятся в ограниченном Swoole Table, без RepositorySaver
  и сохранения в MySQL. После restart не восстанавливать мнимые свежие контакты;
  работающие источники создадут их следующим фактическим сканом.

### Курс в галактике — уточнение 23.10.2026

Первоначально23.10 пользователь выбрал показ **только курса, без конечной точки**;
после согласования26.10 это осталось правилом для score<8. Для активного
внутрисистемного MOVE снимок получает один scalar `course` — азимут скорости
в XY, в градусах [0, 360). Это не полярный угол положения относительно звезды.
Курс 0° действителен; у паузы, истёкшего MOVE и стоянки поля нет.

Клиент использует те же пунктир и стрелку, что у своих/входящих флотов.
Линия проходит через наблюдённую позицию до границ отображаемой системы:
её концы рассчитываются клиентом для рисунка и **не являются стартом/целью
флота**. На score<8 конечная точка, ETA и остальной маршрут в sensor DTO не передаются.
Для нелинейной карты линия и ориентация стрелки проецируются тем же способом,
что обычный внутрисистемный перелёт. Подпись и стрелка доступны для клика.

Свежая отметка жёлтая, устаревшая серая; без курса отображается значок паузы.
До следующего скана позиция и курс остаются неподвижным снимком, а не
интерполяцией скрытого пути. Истечение retention убирает линию, маркер и
открытую карточку. Уже видимые свои/входящие флоты не дублируются контактами.
Карточка поясняет, что линия не обозначает цель; таймер прибытия не добавлен.

## Реализация

- `SetFleetSensors` проходит существующий PlayerQueue и повторную проверку
  владения/условий в EventLoop. ACK сам режим не включает. Изменяется только
  params активного OBSERVE, с существующей локальной компенсацией при отказе.
- Сканирование группируется по активным системам. Позиция и состав цели
  рассчитываются один раз за скан, результат публикуется по одному наблюдателю.
  При отсутствии включённых источников позиции всего мира не рассчитываются.
- `SensorContacts`: 1024 строки, по одному сжатому JSON-снимку на наблюдателя,
  максимум 16 KiB после сжатия/base64 и 1 MiB до него. Native set атомарен;
  при переполнении/отказе остаётся предыдущий снимок и пишется ошибка, а не
  обрезанные данные. Выделено 16 904 240 байт (~16.1 MiB), не по 16 KiB на цель.
- `sensorVersion` не позволяет выключением/включением оживить старый контакт.
  Чтение проверяет существование источника, актуальную команду/фазу цели,
  топливо, бой, поколение источника, но не подменяет позицию живыми координатами.
- Page Overview/Galaxy получают отдельный DTO контакта через прежний ActualData;
  свои/входящие не дублируются. Маркер показывает позицию и курс снимка,
  не интерполяцию скрытого пути. Карточка раскрывает только разрешённые сведения.
  Истечение freshness/retention обрабатывается локально, в том числе в уже
  открытой карточке карты. В селекторе контакты пока disabled, не live-цели.
- Справка технологии 135 показывает действующие эффекты. Описания и баланс
  передаются сервером. Для 221 временно используется существующий spy_sonde.gif,
  отдельная новая иллюстрация не создавалась.
- Миграция `20261023_sensor_scout.php` проверяет конфликты ID/баланса, по умолчанию
  read-only; `--apply` применять при остановленном сервере. Применена дважды
  для проверки идемпотентности; после запуска штатно созданы колонки FleetsShips.

## Исправление lifecycle и recovery B005 — 23.10.2026

Временный Fleet в сенсорном read-path мог удалить настоящий Fleet при GC:
`Fleet::__destruct()` вызывал игровое удаление. Этот destructor удалён;
явные destroy/remove сохранены, свежие чтения Tables не заменены cache.
Новые GC-регрессии увеличили FleetSensorSwooleTest до **14/14**, SQL=0.
«Сенсор» snak84 / #38 восстановлен; настоящий WS подтвердил состав и
включённый OBSERVE в списке флотов и Galaxy 1:9. Подробности, backup и границы
визуальной проверки: [`fleet-sensor-recovery.md`](fleet-sensor-recovery.md).

## Границы и оставшиеся риски

- 3Б ещё не начат: контакт не даёт права на живую цель/боевой перехват.
- Буфер ограничен; при слишком плотной вселенной нужны реальные нагрузочные
  измерения и согласованная политика деградации. Старые снимки не продлеваются
  при неудачном скане. Crash/многопроцессный writer не покрыты локальной компенсацией.
- Не менять ручную фалангу на мобильную формулу: это разные источники/контракты.
- Deferred B001/B002/P001 и обнаруженные B003/T002 не исправлены в этом этапе;
  см. `found-bugs.md`. Старый Fleet baseline тоже не исправлялся.
- При проверке курса отдельно подтверждён B004: pending MOVE с pause=fuel
  получает бонус заметности движущейся цели. Формула не менялась попутно.
