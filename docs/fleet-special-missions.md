# Уничтожение луны и групповая атака

## Уничтожить (`DESTROY=7`, команда `DESTROY=24`)

- Только чужая существующая луна и хотя бы одна Звезда смерти (`214`).
- `LOAD → MOVE… → DESTROY (обычный бой) → MOVE… назад → UNLOAD → STAY`.
- Попытка уничтожения разрешена после победы атакующей стороны при наличии уцелевших ЗС.
- Nova: шанс луны `clamp(round((100 - sqrt(диаметр)) * sqrt(уцелевшие ЗС), 1), 0, 100)`.
- Независимый риск гибели всего атакующего флота: `clamp(round(sqrt(диаметр) / 2), 0, 100)`.
- Отдельный детерминированный поток RNG от seed боя и ID флота: retry не перебрасывает исход.
- Удаление луны, локальных построек/кораблей/обороны/ресурсов/очередей, переназначение текущего объекта игрока,
  баз флотов, входящих/возвратных команд и групп включено в общий runtime commit боя.
- Глобальное исследование не теряется: финансирующий объект очереди меняется на родительскую планету.
- Входящий `DESTROY` исчезнувшей луны становится обычной атакой родительской планеты, как в Nova.
- Гибель при разрушении не добавляет второй порции боевых обломков. Груз и топливо погибшего флота теряются.
- Результаты попытки и риска сохраняются в публичном боевом докладе.

## Групповая атака (`GROUP_ATTACK=3`, команда `GROUP_ATTACK=21`)

- В отправке выбирается новая группа или существующее явное приглашение.
- Приглашение по игровому имени, как в Nova (`ShowFleetTablePage::getACSPageData`): дружба и общий альянс не обязательны.
  Друзья служат только подсказками в поле имени; собственные дополнительные флоты доступны без приглашения.
  Приглашать может только создатель САБ, пока есть атакующие флоты и не наступило время прибытия.
  Владелец цели, несуществующий игрок и повторное приглашение отклоняются; лимит пользователей включает создателя.
- После вылета на карточке флота кнопка **«Группа»** открывает список приглашённых; ввод имени доступен только создателю.
  Также он доступен из выбора существующей группы в отправке флота. Получатель видит обычное игровое сообщение
  и выбирает группу при отправке своей миссии «Групповая атака»; приглашение само по себе не отправляет его флот.
- Группа имеет постоянные ID, цель, `execute_time`, приглашённых пользователей и список флотов.
  Runtime — Swoole Table; MySQL — обычный RepositorySaver. Архитектура PlayerQueue не меняется.
- Новая группа: `data.group={id:0, usernames:["Имя игрока"], executeAt?:unixSeconds}`.
  Прежний `users:[userId,…]` принимается для совместимости с уже поставленными командами.
  Без executeAt сервер использует верхнюю оценку времени вылета на выбранной скорости плюс 30 секунд.
- Приглашение после вылета: `mode=fleets, action=InviteAttackGroup, data={groupId, username}`.
  Проверка до PlayerQueue и повторная проверка в EventLoop; обычный ACK означает приём команды,
  членство и уведомления обновляются через штатный ActualData. Маршрут, топливо и время прибытия не меняются.
- Присоединение: `data.group={id:groupId}`. Сервер повторно проверяет приглашение, цель, срок и лимиты.
- Общее время не сдвигается при присоединении. Если флот не успевает, команда отклоняется до списаний.
- SpeedFactor сохраняется отдельно на каждом MOVE, может быть дробным в диапазоне 1…выбранный игроком максимум.
  Финальный MOVE рассчитывается по положению цели в общий срок. После случайного входа в систему пересчитывается
  оставшийся участок. Preview не выбирает будущий случайный угол входа и не изменяет commands.
- Все готовые одновременные участники собираются до первого раунда, в том числе при пустой обороне.
- Технологии/опыт каждого владельца считаются отдельно. Добыча считается один раз и распределяется по свободной вместимости.
- Каждый флот может быть отдельно отозван; отзыв освобождает членство и не отзывает остальных.
- Настройки: `GroupAttackMaxFleets=16`, `GroupAttackMaxUsers=5`. Срок не дальше семи суток.
- Приглашение использует существующие сообщения/ActualData. Просроченные группы без активных участников удаляются через сутки.

## Образование луны

Основные правила уже соответствовали Nova и не заменялись новой формулой:

`min(MoonChance, round((новый металл + новый кристалл) / 100000 * MoonFactor))`.

Луна образуется только у планеты без существующей луны. Победа атакующего не обязательна.
Старое поле не увеличивает шанс. При успехе `DebrisMoon=1` расходует всё поле, включая старое;
при неудаче или `DebrisMoon=0` обломки сохраняются.

Обнаружена и исправлена утечка из `MoonFormationTest`: `Config::setValue()` писал тестовые `100%/100000`
в настоящую БД. Теперь тест меняет только собственный runtime double. В среде разработки восстановлены
`MoonChance=20`, `MoonFactor=1`, `DebrisMoon=1`; повтор теста не меняет эти настройки.

## Границы

- Нет переноса срока существующей группы, альянсов или преобразования уже летящей обычной атаки в САБ.
- Обычные ограничения боя, топливо после потерь, хранение активных боёв и надёжность PlayerQueue не перепроектировались.
- Старые настройки эффективности `EntitySettings` уничтоженной луны пока могут оставаться как недоступные записи
  с прежним уникальным ID. На ресурсы/новые объекты они не влияют; очистка требует отдельного composite-key lifecycle.

## Уточнение: приглашает только создатель САБ (19.10.2026)

В отличие от исходного правила Nova, приглашённые участники не могут приглашать других игроков.
`prepareInvitation()` сверяет `owner_id` с текущим игроком до PlayerQueue и повторно при исполнении.
`listFor()` передаёт `canInvite`: UI показывает форму приглашения только создателю; остальным
доступны список участников и присоединение своего флота. Без `canInvite=true` форма скрыта.
Проверены 7 сценариев приглашений, native Swoole/TEMPORARY MySQL и обе роли в настоящем SPA
на UI-фикстурах без отправки флотов или новых приглашений.
Сбой уведомления после сохранения членства логируется без повторного добавления игрока;
отдельная надёжная доставка уведомлений и общая межпроцессная сериализация здесь не вводились.
