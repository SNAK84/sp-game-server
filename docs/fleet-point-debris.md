# 3Б.2 — обломки боя в свободной точке

Дата: 24.10.2026. Статус: реализовано, живой рейс #41 завершён.
Следующие этапы обследования и добычи ресурсных объектов не начаты.

## Контракт

- Это существующие `SpaceDebrisFields` в неподвижной физической POINT боя,
  не орбитальное поле `DebrisFields`, не новая планета и не сенсорный контакт.
- Поля публичны в выбранной системе, как обычные орбитальные обломки.
  Galaxy передаёт только id, координату, металл и кристалл. Battle id,
  участники, команды и скрытые положения флотов в DTO не входят.
- Нажатие на поле открывает карточку запасов; кнопка переводит в обычное
  окно отправки с точной POINT и миссией RECYCLE (id 12 не изменён).
- Обычный путь: LOAD → MOVE → RECYCLE → MOVE домой → UNLOAD → STAY.
  Действуют существующие расчёты топлива, загрузки, трюма и сообщения.
- Миссия доступна только при положительном запасе и кораблях с capability
  RECYCLE. Вместимость транспорта сопровождения не заменяет переработчики.
- Собирается актуальный запас по прибытии, в пропорции металл/кристалл,
  не больше свободного трюма и вместимости переработчиков.
- Пустое поле по прибытии даёт нулевой сбор, а не повторный ресурс или
  зависание возврата. Принятый POINT-этап не теряет достижимость из-за
  чужого сбора; состав переработчиков по-прежнему проверяется.
- Физическая точка боя может оказаться вне обычных границ удержания.
  Исключение ограничено существующим полем, с допуском 0.05 игровых единиц;
  произвольные координаты и OBSERVE вне границ не открываются.

## Runtime commit и доставка

Перед сбором снимаются запасы полей, груз и строка команды. Изменения полей,
груза и executed проверяются по Swoole Tables и dirty markers. При исключении
восстанавливаются снимки; attempted index команды компенсируется локально.
При ошибке самой компенсации — CRITICAL и попытка диагностической паузы.
Это не гарантия восстановления при отказе Swoole Tables и не общий механизм
транзакций. MySQL не является источником runtime state.

Нулевые строки остаются в хранилище: история battle_id не должна породить
обломки заново при повторном применении боя. На карте нулевые поля скрыты.
Обычный RepositorySaver сохраняет изменения; он не изменялся.

Появление поля после боя и изменение после сбора ставят существующий
`SendActualeData` только онлайн-зрителям этой системы. Используется сохранённый
`Connect::getGalaxyView()` и обычный PlayerQueue/EventLoop; новых каналов,
периодического опроса карты или самостоятельной push-архитектуры нет.

## Исправления формы

POINT из Galaxy сохраняется до получения NavigationSystem, но отправка
остаётся заблокированной до проверки системы. Расстояние и угол используют
дробный number input: общий integer helper ранее удалял десятичную точку
на blur. Редактор маршрута теперь не превращает RECYCLE/POINT в OBJECT.
NavigationSystem содержит публичные debrisPoints для точного исключения
из обычного min/max, не для расширения всех свободных координат.

## Ограничения проверки

Не имитировались отказы записи/rollback, конкуренция нескольких mutation
workers, частичный сбор полным трюмом, несколько совпадающих POINT-полей,
перелёт к уже опустевшему полю из другой системы и поле за min/max.
Последние пути проанализированы в коде, но не объявляются живыми тестами.
Нулевые поля занимают место в существующей ограниченной Swoole Table;
политика их архивирования в этом подэтапе не вводится.

Известный B001 (detach страницы старым Hide) вновь встретился при переходах;
проверка карты проводилась только после восстановления видимого DOM.
Он остаётся в `found-bugs.md`, общий page lifecycle не менялся.
