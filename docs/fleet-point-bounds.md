# Свободные точки и запас топлива для удержания

23.10.2026. Исправление по замечанию пользователя после этапа мобильных сенсоров.
Минимум выбран явно: `Galaxy.min_distance` конкретной системы; не центр звезды.

## Причины

- Обычная форма использовала условные 0–16000; navigation API передавал только
  границы номеров орбит. При POINT смена типа не запрашивала границы системы.
- Сервер уже запрещал POINT за орбитой SYSTEM_EDGE, но разрешал расстояния от 0.
- В редакторе маршрута POINT не запрашивал navigation info; у расстояния не было
  системного max. Серверная валидация этапов при этом существовала.
- Для OBSERVE сервер уже разрешал запас сверх расхода перелёта, ползунок тоже
  показывал вместимость. Но `getLoadError()` применял к нему максимум конечной
  миссии, поэтому кнопка отправки оставалась заблокированной.

## Контракт после изменения

- Пользовательская цель POINT: **min_distance ≤ distance ≤ SYSTEM_EDGE.distance**.
  Границы включены; орбита экспедиции не превращается в свободную точку.
- `FleetMissionService::pointDistanceBounds()` читает общие границы; они же
  возвращаются прежним `GetSystemNavigationInfo` как minDistance/maxDistance.
- Форма и редактор запрашивают их также для POINT, обновляют min/max и приводят
  значение к диапазону при получении границ и завершении ввода. Во время загрузки
  новое расстояние не считается подтверждённым. Первый символ числа не должен
  принудительно превращаться в min_distance: нижний предел применяется по blur/change.
- Сервер повторно проверяет расстояние при подготовке/исполнении команды и
  компиляции этапов. Подделанный клиент и устаревший preview не обходят ограничение.
- Это **не** ограничение `Coordinate::point()` или физических траекторий:
  внутренний расчёт, текущее положение/остановка ниже min и существующие полёты
  не перемещаются искусственно. Новые пользовательские цели должны быть допустимыми.
- Для OBSERVE запас ограничен свободной вместимостью и дейтерием источника;
  груз вместе с баком не превышает вместимость. Минимум перелёта сохраняется.
  Это запас на бессрочное удержание, а не новый конечный расчёт его длительности.
- Для транспорта и остальных конечных миссий максимум топлива не увеличен.
  Формулы расхода/времени, технологии, RepositorySaver и PlayerQueue не менялись.

Примеры реально проверенных систем: 1:8 — **736–6952**, 1:10 — **1127–21892**.
Не применять эти числа глобально: границы берутся из каждой конкретной системы.

## Проверки

- `FleetPointBoundsSwooleTest`: **5 passed / 0 failed, SQL=0**;
  `/tmp/sp-game-flight-audit-oi8yxa9x`.
  Включённые границы, epsilon за границами, NaN/INF, разные/неизвестные системы,
  неверный тип служебной орбиты, изменение границ после preview, обход через
  move/mission в плане, отсутствие runtime мутаций при отказе. Запас сверх
  расчётного max загружается один раз и расходуется при удержании; нехватка
  вместимости/дейтерия и превышение максимума конечной миссии отклоняются.
- FleetFreeSpace (host/native), FleetPlan, FleetPlanAvailability, FleetSensor,
  FleetRendezvousFuel, FleetRouteProjection, FleetRecallTiming — пройдены.
- Legacy baseline: прежние **25 failed / 5 passed**, набор имён тот же;
  `/tmp/sp-game-flight-audit-m5rr4z6u/results.json`.
- Финальный browser UI: **7/7**, `/tmp/fleet-mission-layout-ul_35f8h`.
  Реально видимый диалог и отсутствие overflow на 1440/390/320 px; запас
  5000 при расчётном max=4 не блокирует OBSERVE. Конечный транспорт сохраняет
  max=16. Маршрут 1:8→1:10→1:8 обновляет min/max. Проверены нижний/верхний предел
  и ввод допустимого расстояния по одной цифре, без прыжка к минимуму.
- UI regression мобильных сенсоров после изменения: **5/5**,
  `/tmp/fleet-mission-layout-rcsuh752`. PHP lint, Chromium JS parse, Python syntax
  и scoped diff check пройдены. После перезапуска в stdout основного серверного
  процесса ERROR/CRITICAL нет; ожидаемые ошибки isolated fixtures не смешивать
  с runtime-проверкой (T002 в реестре).
- Browser helper: `python3 tools/check_fleet_point_bounds.py` — только чтение API
  и незаписанные формы; `--execute` — явный тестовый вылет snak1/Fleet #3 с 1000
  топлива, штатный Stop, удержание и возврат. Он не выдаёт корабли/ресурсы и не
  меняет технологии, часы или скорость игры.
- Реальная отправка OBSERVE с 1000 топлива принята; расчётный максимум перелёта
  был 4. После Stop active hold имеет ~999.19 топлива, rate=1/3600 дейтерия/с.
  Сохранился запас и вернулась неиспользованная часть предоплаченного MOVE;
  это не повторный возврат топлива с планеты. Артефакты:
  `/tmp/fleet-mission-layout-e8irub7z/hold-start.json`.
- Cleanup: в 13:21 МСК Fleet #3 штатно вернулся на Homeworld, status=0,
  исходный малый транспорт сохранён, бак после выгрузки пуст. Остаток топлива
  обработан обычным UNLOAD; никаких ручных возвратов/SQL-правок нет.
  `/tmp/fleet-mission-layout-e8irub7z/hold-returned.json`.
