# B013 — применение координат в галактике

01.11.2026. Production-изменения только в SPA `js/pages/GalaxyPageClass.js`.
Backend, WebSocket-протокол, генератор, физика систем и настройки мира не меняются.
Перезапуск игрового сервера для клиентской правки не нужен.

## Причина и воспроизведение

До исправления повторено на основном dev в настоящем SPA под QA:
на карте1:7 в поле системы введено8, затем настоящий Enter и клик вне поля.
Поле осталось8, `Page.System.system` —7; исходящих galaxy-запросов0.

Оба numeric input вызывали только `renderNavigation()`, обновляющий disabled
у стрелок. `initNumericInput` уже передавал input/blur, но blur не применял
координаты. Обработчика Enter не было. Запрос существовал только в другом
методе `NavigationEvent()` для кнопок; «Показать систему» работала отдельно.

## Исправление

- Ввод цифр по-прежнему меняет только поля и доступность стрелок, без запросов
  на каждую цифру. Enter и blur применяют оба поля через `NavigationEvent()`.
- Blur перед кликом «Показать систему» или стрелки не делает промежуточного
  перехода: координаты применяет сама кнопка. Стрелки отсчитывают от полей,
  как и их состояние disabled, а не от старого snapshot системы.
- Перед отправкой координаты становятся целыми числами в1..MaxGalaxy/MaxSystem
  из актуального server Page. Поля синхронизируются с отправленными числами.
- Локальный `navigationTarget` исключает повтор того же ожидающего перехода.
  Неизменённые поля не запускают переход снова; отдельная кнопка «Показать
  систему» сохраняет явное обновление уже открытой системы.
- Маркер снимается после ответа/ошибки и при Hide. После ошибки можно повторить
  ту же цель. Существующие request scope и `latestKey: galaxy` не менялись;
  новой транспортной схемы или клиентского хранилища не добавлено.
- Переход системы использует существующий `NotOverlay: true`: запрос отправляется
  сразу, а карта сохраняет собственную анимацию загрузки. Иначе общий Overlay
  мог отменить ещё не отправленный запрос, оставив локальную цель занятой.
  Это проверено до добавления флага UI-replay старого настоящего snapshot:
  target=1:14, pending WS=0, отправок0, фактически осталась1:6. Общий Overlay,
  отправка меню и находка B037 этим локальным обходом не исправляются.
- Проверки цели выполняются до закрытия карты/панелей и запуска анимаций.
  Постоянные элементы навигации и canvas не пересоздаются.

## Живая проверка

```bash
python3 /var/www/spa.snak84.ru/tools/check_galaxy_navigation.py --session ID
python3 /var/www/spa.snak84.ru/tools/check_galaxy_navigation.py --session ID --mobile
```

Нужна своя уже открытая авторизованная Selenium-сессия основного SPA.
Скрипт не получает credentials, не запускает второй мир, не меняет конфигурацию
и запрещает игровые команды. Чтение систем использует настоящий сервер.

Задержанные ответы проверяются удержанием доставки уже полученного настоящего
ответа в UI; после нового перехода он отпускается через штатный обработчик.
Проверка ошибки — отдельно помеченная client-side инъекция ошибки ожидания,
не реальная ошибка сервера. Быстрый ввод проверяется настоящей клавиатурой
в сфокусированном поле. Вспомогательный UI-replay старого DTO в одном task
проверяет, что render не отменяет отправку нового запроса; это не новый ActualData.

В текущем dev сервер сообщает MaxGalaxy=1, MaxSystem=128. Проверяются обе
границы системы и галактики, но переход в другую разрешённую галактику здесь
невозможен. Для теста лимит не увеличивается и другая галактика не создаётся.

Desktop1365×900 и мобильная ширина390×844: по25 проверок и19 настоящих
запросов систем; JS errors=0, pending requests=0, WebSocket открыт в обоих
прогонах. Проверены настоящий набор/Enter/blur,
дедупликация и явное обновление, стрелки от введённой координаты, min/max,
оба поля, запоздалый ответ/уход со страницы, повтор после ошибки и отправка
независимо от render в том же task. Тот же Page response сохраняет черновик,
фокус и DOM; canvas/поля переживают переходы между системами, overflow нет.

Предварительные прогоны не засчитывались: сначала драйвер пытался кликнуть
сквозь штатный overlay, затем возврат меню начался до завершения render обзора
(отдельная граница B037). Для проверки быстрых переходов используется клавиатура,
а служебный возврат теста — существующий read-вызов без новой анимации меню.
Общие `base.js`, `BasePageClass.js`, `Dialog.js` не изменялись.

Python syntax и точечные diff-check пройдены; JS загружен и выполнен Chromium.
Игровой контейнер работает без перезапуска с31.10.2026 21:46:25 UTC. После
прогонов карта1:6 видима, WebSocket открыт, pending=0, navigationTarget=null.
В7988 свежих строках Docker-лога с22:32 UTC нет ERROR/CRITICAL/Fatal; содержимое
авторизационных записей и токены не выводились. Своя Selenium-сессия проверки
закрыта после завершения прогонов.
