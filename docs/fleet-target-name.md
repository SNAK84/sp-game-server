# B019: пользовательское имя цели-флота

01.11.2026. Изменён только один production-файл текущего SPA:
`js/pages/FleetsPageClass.js`. Backend, протокол и схема БД не менялись;
перезапуск основного Swoole не требовался.

## Причина

Сервер уже передавал имя своего флота в FleetTargets/FlyingFleets.
Picker использовал это имя, но общий formatFleetCoordinate(type=3)
безусловно возвращал «Флот #ID». Из него получали подписи карточка,
список команд, редактор маршрута и tooltip при FLEET-координате.
Это не отсутствие server state и не пересоздание DOM.

## Исправление

- Запись ищется только в текущем разрешённом Page: FleetTargets → FleetList →
  FlyingFleets. Имя отсутствующей/безымянной записи заменяется «Флот #ID».
  При найденной записи с пустым именем поиск старого имени в других DTO не
  продолжается. Отдельного кеша имён, чтения SensorContacts/_observation,
  запросов к живому Fleet и раскрытия lastKnownPosition не добавлено.
- formatNavigationTarget делегирует FLEET-подпись тому же formatter.
- Command target передаётся в HTML-tooltip через текстовый span: имя остаётся
  текстом, а не разметкой. Остальные потребители уже используют text().
- Существующие DOM-узлы, CSS, поведение выбора цели и отправка не переписаны.

Browser-fixtures покрывают приоритет источников, числовой/строковый ID,

восстанавливается в finally. Они не выданы за серверный тест видимости/боя.

## Важные границы

Tooltip прогресса по-прежнему показывает **текущий участок**, не конечную
цель всей миссии. В живом рейсе132 server segment_target — POINT3000/0°,
а mission_target — FLEET131. Точка в tooltip не подменялась именем общей
цели; его FLEET-ветвь отдельно проверена browser-fixture.

Во время подготовки тест сначала менял скорость только через input.
Клиент рассчитывает новый preview на change, поэтому автоматизация отправляла
новую скорость со старым количеством топлива и получала штатный preflight
отказ «Нельзя загрузить больше рассчитанного максимума топлива».
Исправлен тест (input+change, ожидание нового preview), не игровая формула.
Это не подтверждённый новый баг; в реестр отдельный номер не добавлен.

Для уборки восстанавливается имя131. Транспорт отзывается RecallFleet,
уже возвращающийся флот повторно не отзывается; удержание OBSERVE штатно
завершается через ResumeFleet/available с продолжением готового возврата.
Это существующие разные действия, а не исправление механики возврата.

Изолированный мир/сервер не запускался. Node и конфигурация ESLint/Prettier
в текущем проекте не найдены: JS проверен загрузкой реального клиента в Chromium и
исполнением изменённых ветвей; Python — py_compile; собственный diff — от
backup, дополнительно git diff --check. B043 и остальные отдельные баги
не исправлялись. Повторно проверять всю физику/бой для этого UI-патча не требовалось.

В финале основной сервер Running=true/OOMKilled=false, прежний startup
`2026-11-01T06:49:10.670367726Z`: перезапуска не было. В Docker-журнале за этап
ERROR/CRITICAL/WARNING0 и PHP Fatal/Warning0; в browser-regression JS errors0.
Это не утверждение об отсутствии старых предупреждений в файловых журналах;
логи не очищались. Собственная Selenium-сессия закрыта после проверки:
обе карточки QA видимы, имена восстановлены, pending WS0/JS errors0.
