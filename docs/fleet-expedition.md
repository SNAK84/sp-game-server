# Экспедиция

Реализовано для текущего command-based runtime. Исторические движки использованы
только как образцы: Nova `MissionCaseExpedition.class.php` и SP-Game v1
`class.FlyingFleetHandler.php::MissionCaseExpedition`.

## Отправка и время

- Миссия 40, без изменения числовых enum. Цель — существующая служебная
  `GalaxyOrbits::EXPEDITION` в той же системе. OBJECT без `ObjectType`, с углом флота.
- Требуется астрофизика 1. Лимит одновременных экспедиций — `floor(sqrt(level))`;
  возвращающаяся экспедиция продолжает занимать слот. Общий лимит миссий тоже действует.
- Выдержка — целые часы от 1 до уровня астрофизики, по умолчанию 1 час.
- Цепочка: `LOAD → MOVE_IN_SYSTEM → EXPEDITION → MOVE_IN_SYSTEM → UNLOAD → STAY`.
  Отдельной WAIT нет. `EXPEDITION.execute_time` — ближайшее часовое событие:
  `arrival + (events_done + 1) * 3600`. Полный конец обследования хранится отдельно
  в `params.expedition.endsAt = arrival + duration` и используется UI/projection.
- UI показывает выдержку, занятые слоты, предупреждение о рисках и прогноз возврата.
  До определения исхода прогноз не является обещанием точного возвращения.
- Отзыв во время обследования возвращает флот с уже полученными находками; во время NPC-боя и
  фиксации результата изменение флота блокируется. Будущие команды можно редактировать
  по существующим технологическим ограничениям; уже активная команда не переписывается.

## События и стартовый баланс

Каждый полный час — отдельное событие, включая «ничего». Находки и потери
применяются сразу, итоговый отчёт отправляется один раз после всех часов либо
при отзыве, если завершён хотя бы один час. При гибели дальнейших событий нет.
Пропущенные во время простоя часы обрабатывает тот же scheduler без повторного
применения результата; seed различается по номеру часа, а checkpoint сохраняется.

Nova выбирает шесть событий по 1/9, ещё 3/9 — ничего. Эти веса сохранены по умолчанию.
Следовательно, полная потеря сама по себе имеет вероятность 1/9 **за каждый час**, не считая NPC-боя:
риск существенный и требует отдельного балансирования перед публикацией игры.

| Событие | Реализация |
| --- | --- |
| Ресурсы | Металл/кристалл/дейтерий с весами 3/2/1; ограничены свободным трюмом с учётом топлива |
| Валюта | **Кредиты**; 100–300, реже 301–600, очень редко 601–3000; грузятся в `fleets.resource_credit`, не занимают трюм, зачисляются только на базе |
| Корабли | Типы из состава экспедиции, кроме колонизатора, переработчика и Звезды смерти; нулевой опыт у находок |
| NPC-бой | Пираты или чужие; относительная численность и технологии по Nova, текущий групповой калькулятор SP-Game |
| Потеря | Удаление флота, его кораблей и команд; груз, топливо и находки утрачены |
| Аномалия | Возврат ×2/×3/×5 либо ×1/2, ×1/3, ×1/5; меняется длительность, не ручной SpeedFactor |
| Ничего | Час без находок; следующий час либо обычное возвращение |

Аномалии не сдвигают часы обследования. Последняя аномалия задаёт множитель
обратного перелёта (множители не перемножаются); он сохраняется и при отзыве.

Веса настраиваются отдельными scalar config keys:
`ExpeditionWeightResources`, `ExpeditionWeightCredits`, `ExpeditionWeightShips`,
`ExpeditionWeightCombat`, `ExpeditionWeightLost`, `ExpeditionWeightTime` (по умолчанию 1),
`ExpeditionWeightNothing` (3). Все нулевые веса недопустимы. Отсутствующие ключи
используют defaults; игровые config rows при установке не перезаписываются.

Ресурсные очки — количество кораблей × цену металл+кристалл × 0.005. Default
`ExpeditionPointsCap=2400`: это начальный фиксированный cap, а не зависимость
от отсутствующего в новом движке рейтинга первого игрока. Бюджет кораблей — Nova:
минимум 10000, сверху используется `min(points,4500)` и коэффициент редкости.

Найденные корабли получают запас на обратный полёт; если они вместе с топливом
не помещаются, находка не принимается. Средний опыт флота пересчитывается,
накопленный опыт прежних кораблей не увеличивается искусственно.

NPC клонирует пропорциональный состав экспедиции; дополнительные шаблонные
корабли старого движка не добавляются. Раунды считаются отдельными заданиями
существующего TaskWorker pool, один раунд на игровой poll. Потери топлива — по доле
утраченной вместимости, груз ограничивается оставшимся трюмом. Опыт и доклад используют
обычные сервисы боя. Планета не блокируется, поля обломков и луны здесь не создаются.

## Состояние и ошибки

`FleetExpeditions` — отдельный runtime repository (128 записей, до 256 KiB каждая)
с обычной периодической синхронизацией в MySQL `fleet_expeditions`.
Схема создаётся штатной инициализацией repository при старте сервера.

Сохраняются фаза, исходный seed, время обследования, история часовых событий,
NPC-round checkpoint и признак отправки итога. Кредиты — существующий ресурс Fleet,
а не начисление на аккаунт в момент события. Seed и будущий исход не отправляются клиенту.
Игровые изменения применяются локальной компенсацией только затронутых строк;
ошибка записи восстанавливает предыдущие строки. Отдельный prepared/published
боевой архив использует уже существующий механизм BattleReports.

После сбоя публикации результат повторяется без повторных потерь/награды; retry
откладывается на 5 секунд, чтобы другие Fleet events могли обрабатываться.
Потерянное CPU-задание восстанавливается с тем же seed; timeout 60 секунд,
после трёх неудачных повторов бой останавливается для диагностики без применения потерь.
Такой Fleet защищён от редактирования, но не блокирует обработку остальных флотов.

Один сводный итог: рассказ о произошедших событиях по образцу старого SP-Game,
суммарные находки, оставшийся груз (включая кредиты) и ссылки на боевые доклады.
Повторившиеся события сгруппированы; пустые блоки находок не показываются.
Часовых писем нет. После фактического прибытия и выгрузки на базе отправляется
отдельное уведомление с доставленным грузом, кредитами и остатком топлива.
Отзыв до первого события не создаёт отчёта, но возвращение подтверждается сообщением.
Используется прежний PlayerQueue → ActualData/messages push, без нового протокола.

## Проверки

- `php tests/FleetExpeditionTest.php`: 25 узких сценариев, включая все исходы,
  ограничения, ACK, отзыв, failure injection, повтор, прогноз, вместимость и опыт,
  восстановление потерянного worker mailbox с сохранением seed раунда,
  три часовые находки, отзыв до/после первого часа, потерю бортовых кредитов,
  отсутствие объёма у кредитов и retry промежуточного checkpoint.
- В контейнере: `php tests/FleetExpeditionSwooleTest.php`: настоящие Swoole Tables,
  семь исходов и два часовых сценария, отдельные дочерние процессы на раунды,
  SQL запрещён fixture guard.
- В контейнере: `php tests/FleetExpeditionPersistenceTest.php`: три checkpoint-фазы,
  реальная MySQL TEMPORARY table, reload и DELETE; игровые строки не затрагиваются.
- Регрессии: FleetStage3Test, FleetFreeSpaceTest, BattleReportPipelineTest,
  FleetRecallSwooleTest, FleetRecallTimingSwooleTest.
- Настоящая SPA на snak1: выбор и отмена выбора экспедиции, correlated
  GetAvailableMissions/TravelInfo, payload с duration и OBJECT без ObjectType;
  desktop и 390 px без горизонтального переполнения. SendMission в живую игру
  при этой проверке не отправляется. Renderer-проверки трёх фаз и семи сообщений
  получают DTO из `tests/fixtures/expedition-browser.php`, а не из MySQL игры.

Ограничения: общей атомарности нескольких repositories при аварийном завершении
процесса до saver нет; компенсация сама может отказать (отдельный CRITICAL log).
128 одновременных checkpoint записей и размер JSON — явные runtime пределы.
Долгий реальный часовой полёт не заменяется ускоренным fixture-тестом.
Отдельно от этого изменения: при уничтожении возвращающейся экспедиции внешним
планетарным боем Fleet удаляется, но его запись FleetExpeditions явно не очищается.
Бортовые кредиты не зачисляются, однако остаётся orphan checkpoint; cleanup этого
внешнего lifecycle требует отдельной проверки.

Проверка UI на 390 px выполнена открытием окна уже на мобильной ширине. У ранее
открытого desktop-диалога при резком уменьшении viewport остаётся старая геометрия;
это существующий отдельный resize-case, в данном изменении не исправлялся.
