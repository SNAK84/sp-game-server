# Опыт кораблей и сводный опыт флота

Статус на 16.10.2026: расчётная часть внедрена в `FleetExperienceService`;
производный опыт флота подключён к `Fleet`. Сам бой ATTACK и применение награды
его handler-ом ещё не реализованы. Полноценного боевого испытания модели нет.

## Текущая граница реализации

- `FleetExperienceService::bonuses()` и `combatStats()` рассчитывают бонусы.
  Они ещё не вызваны боем, поскольку исполнителя ATTACK пока нет.
- `sidePower()` и `calculateRewards()` готовят награду из snapshot результата,
  не меняя ни Fleet, ни repositories, ни marker команды.
- `Fleet::getExperience()` вычисляет показатель из суммарного опыта кораблей;
  `Fleet::save()` обновляет существующее поле-кэш при сохранении кораблей.
- `FleetShip::setExperience()` отклоняет NaN/Infinity до мутации и callback.
- Формат WebSocket, БД, RepositorySaver и отправка миссий не менялись.
- Runtime exactly-once, rollback всего боя, топливо, добыча и отчёт относятся
  к следующему этапу ATTACK; повторный чистый расчёт не доказывает exactly-once.
- `FleetCombatService` отдельно рассчитывает раунды, потери и урон каждой группы;
  `experienceInputs()` готовит вклад после явно переданного восстановления обороны.
  Это пока не исполнитель миссии и не применение опыта. Правила и калибровка:
  [групповой боевой расчёт](fleet-combat.md).

Пример внутреннего контракта (не WebSocket request):

```php
$result = FleetExperienceService::calculateRewards([
    'fleet:17:204' => [
        'before' => 100, 'after' => 40, 'experience' => 10000.0,
        'unitCost' => 4000.0, 'contribution' => 200000.0, 'eligible' => true,
    ],
], ownPower: 1000.0, enemyPower: 1000.0, destroyedValue: 200000.0);
```

Подготовленная группа имеет 4400 суммарного опыта: 4000 сохранившегося и 400 нового;
средний опыт — 110. Сервис сам не записывает этот результат. `combatStats()`
принимает характеристики одного корабля, технологические факторы и средний опыт
его группы, а не общий опыт флота. Неиспользованные доли награды не перераспределяются.

## Утверждённые правила

- Опыт принадлежит кораблям. Опыт флота вычисляется из опыта его кораблей.
- Между флотами опыт переносится вместе с кораблями.
- При переводе кораблей на планету опыт переведённой части теряется.
- Корабли вне флотов участвуют в обороне, но опыт не получают.
- Потеря топлива в бою пропорциональна потерянной вместимости, не количеству кораблей.

В актуальном коде `FleetsShips` уже хранит суммарный опыт каждого типа кораблей.
`FleetsServices::MoveShip()` переносит эту сумму пропорционально количеству;
планетарный `Ships` хранит только количество. `Fleet.experience` используется
только как производный кэш: чтение Fleet не доверяет ему вместо опыта кораблей.

## Единица опыта и предел

Для группы одного типа внутри одного флота:

```text
N = количество кораблей
E = сохранённая сумма опыта группы
e = E / N — средний опыт одного корабля; при N = 0 считаем e = 0
0 <= e <= 1000
```

Это опыт экипажей на нормализованной шкале, не число уничтоженных кораблей.
Одинаковые 100 очков дают одинаковый относительный модификатор типа независимо
от того, лёгкий это истребитель или звезда смерти. Цена типа учитывается в награде.
Текущая модель агрегированная: история каждого отдельного корабля не хранится.

## Влияние на характеристики

```text
f(e) = 1.1 * clamp(e, 0, 1000) / (100 + clamp(e, 0, 1000))

Attack = BaseAttack * (KAttack + 0.10 * f(e))
Hull   = BaseHull   * (KHull   + 0.10 * f(e))
Shield = BaseShield * (KShield + 0.05 * f(e))
```

`K` — существующий коэффициент соответствующей технологии и иных боевых бонусов,
без опыта. Для базовых технологий Nova это `1 + 0.1 * уровень + другие бонусы`.
Соответствие имён: military_tech — атака, defence_tech — щит,
shield_tech — корпус. В текущих Vars поля bonusAttack/bonusDefensive/bonusShield
у технологий 109/110/111 равны нулю: прибавку за их уровень нужно учесть явно
в будущем боевом расчёте и не продублировать через Factors.

Базовый корпус для адаптации Nova: `(cost901 + cost902) / 10`.

| Средний опыт | Атака и корпус: прибавка от базы | Щит: прибавка от базы |
| ---: | ---: | ---: |
| 0 | 0% | 0% |
| 25 | 2,20% | 1,10% |
| 75 | 4,71% | 2,36% |
| 150 | 6,60% | 3,30% |
| 300 | 8,25% | 4,13% |
| 600 | 9,43% | 4,71% |
| 1000 | 10,00% | 5,00% |

Это проценты базовой характеристики, не дополнительный множитель уже усиленной
технологиями характеристики. Например, базовая атака 100, технология 10:
новичок имеет 200, корабль с e=1000 — 210, то есть преимущество 5%, а не 10%.
Максимум опыта эквивалентен одной ступени оружейной/броневой технологии и
половине ступени щитовой, а не постоянно растущему числу технологических уровней.

«Бонус применяется один раз» означает: усиливается группа кораблей по её e;
сводный опыт флота не добавляет второе усиление поверх этого. Группы с разным
опытом имеют разные характеристики даже внутри одного флота.

Все раунды боя используют опыт на начало боя. Новый опыт начисляется после
расчёта исхода и влияет только на последующие бои. Он не расходуется при выстреле.

На первом этапе опыт не меняет скорость, топливо, вместимость, скорострельность,
лимиты флотов, время исследований, мораль или шанс восстановления обороны.
Это сохраняет существующие расчёты перелёта и исключает дополнительные слои усиления.

## Начисление за бой

Атакующий и защитник рассчитываются симметрично. Бонуса только за победу нет:
проигравшие выжившие могут получить опыт за реально уничтоженного противника.

### Стоимость и оценка угрозы

```text
C_i = базовая цена одного корабля/орудия в металле + кристалле
V_i = N_before_i * C_i
V_side = сумма V_i всех участников стороны

A_side = суммарная атака с технологиями и исходным опытом, до случайного разброса
H_side = суммарный корпус
S_side = суммарные щиты
P_side = sqrt(A_side * (H_side + S_side))

q = min(1, P_enemy / P_side)^2
```

Если собственная P_side = 0, награды нет. Если P_enemy = 0, q = 0.
Оценка угрозы — только коэффициент награды, не замена боевого расчёта:
она не предсказывает исход, не учитывает все контрсоставы/скорострельность
и подлежит калибровке на реальных боях. Щитовые купола берутся с нулевой атакой,
как в локальной Nova, а не с техническим значением 1 из Vars.

Обе стороны включают ВСЕ действительные боевые группы: флоты, корабли планеты,
оборону. Нельзя оценивать угрозу отдельно для маленького флота рядом с большой
планетарной армией и выдавать ему награду как за самостоятельную победу.

### Общий бюджет награды

```text
D = уничтоженная стоимость противника в металле + кристалле
B = 20 * min(D, V_side) * q
```

В D входят погибшие корабли и невосстановленная часть уничтоженной обороны.
Не входят поглощённый щитами урон, повреждения выживших, восстановленная оборона,
здания, награбленные ресурсы, топливо или груз. Обломки не вычитаются из D:
это цена уничтоженных единиц, а не сумма окончательно исчезнувшего сырья.

Восстановление обороны рассчитывается перед D. Если в будущем появится
самостоятельное восстановление кораблей, определение D потребуется пересмотреть.

### Доля каждой группы

Боевой расчёт должен дать вклад d_i каждой группы в D. Для каждого уничтоженного
типа противника его стоимость распределяется между источниками пропорционально
нанесённому ими урону корпусу этого типа, не по последнему выстрелу.
Урон только щитам не даёт такой доли. Сумма d_i равна D, включая вклад
планетарных кораблей/обороны и впоследствии погибших групп.

```text
w_i = 0.8 * (d_i / D) + 0.2 * (V_i / V_side)
g_i = min(20, B * w_i / V_i)
```

Реализация проверяет совпадение суммы d_i с D. Для допустимой погрешности
дробных значений доля нормализуется на фактическую проверенную сумму d_i,
чтобы округление не увеличивало бюджет. Нулевая сумма при положительном D
или положительный вклад при D=0 отклоняются, даже если числа очень малы.

При D = 0 g_i = 0 без деления. Группы с N_before = 0 не участвуют;
положительные конечные C_i и значения характеристик обязательны.

80% бюджета связано с реальным вкладом, 20% — с участием под угрозой в составе
стороны. Транспорты могут получать небольшой опыт участия в настоящем бою,
даже если наносят мало урона. Простое присутствие рядом с безоружной целью
не даёт награды, так как q = 0.

Доли погибших кораблей, групп с достигнутым пределом и участников без права
на опыт НЕ передаются оставшимся флотам. Планетарные корабли и оборона
учитываются в расчёте долей, но собственную долю опыта не сохраняют.

### Потери и выжившие

```text
e_before_i = E_before_i / N_before_i
E_after_i = N_after_i * min(1000, e_before_i + g_i)
```

Опыт погибших списывается пропорционально потерям внутри типа. Старый опыт и
награда не концентрируются на нескольких выживших. При N_after = 0 E_after = 0.

Проверяемый предел общего начисления:
`sum(C_i * earned_E_i) <= B`, где earned_E_i — только новый опыт выживших.
Это исключает умножение бюджета количеством флотов или числом дешёвых кораблей.
Никакой отдельной награды за факт запуска команды/число раундов нет.

## Сводный показатель флота

```text
e_fleet = sum(C_i * E_i) / sum(C_i * N_i)
```

Пустой флот имеет e_fleet = 0. Это средний опыт с весом по базовой стоимости,
не сумма и не среднее по числу кораблей. Например, звезда смерти за 9 млн с
нулевым опытом плюс 1000 зондов по 1000 с опытом 1000 дадут e_fleet = 100,
а не почти 1000. Этот показатель нужен карточке, рангу и сортировке, но не
заменяет опыт отдельных групп и не усиливает их повторно.

Ранги для отображения, без отдельных ступенчатых бонусов:
0 — новички; 25 — обученные; 75 — опытные; 150 — ветераны;
300 — элита; 600 — гвардия; 1000 — легендарные.

## Переносы и сохранение

Для переноса m кораблей одного типа: `transferred_E = E_source * m / N_source`.
Источник теряет эту сумму; другой флот получает её, планета — нет.
Новые корабли с планеты увеличивают N, не E. Их включение разбавляет средний опыт.
Не округлять E до целых при переносе и не пересчитывать его из округлённого UI.

Объединение равномерно усредняет опыт в пределах одного типа: существующая
структура не различает ветеранов и новичков этого типа после смешивания.
Из-за нелинейной кривой суммарная боеспособность после такого усреднения может
измениться, хотя сумма опыта сохранится. Это ограничение агрегированной модели,
а не обещание сохранить индивидуальные биографии кораблей.

Начисление должно входить в единый runtime commit боя вместе с потерями, добычей,
топливом, обломками и marker команды. Повторный вызов не должен выдавать награду
снова. При rollback восстанавливаются и N, и E; при уничтожении флота его
derived показатель не остаётся независимым источником опыта.
Нужны проверки записи в Swoole Tables и согласованности кэша FleetsData.

## Защита от прокачки и ограничения

- Пустые объекты и бои без уничтоженных единиц дают 0 опыта.
- Зонды/спутники без боеспособного сопровождения дают 0 по q.
- Восстановление щитов и обороны не создаёт повторяемую награду само по себе.
- Распределение награды учитывает всех участников, а не только получателей XP.
- Максимум — 20 среднего опыта за бой, общий предел — 1000.
- Нет опыта за простой, километры полёта, перевозку собственных ресурсов,
  отмену команды или повторную доставку одного результата.
- Материально затратный сговор двух аккаунтов математикой полностью не исключён.
  До массового тестирования нужны логи повторных противников/наград и оценка
  таких боёв; автоматические дневные ограничения пока не предлагаются.
- Большие значения уже сохранённого опыта требуют отдельной проверки данных
  перед внедрением; эта спецификация не сбрасывает существующие записи.

## Расчётная проверка

Production-формулы: `php tests/FleetExperienceTest.php`. Проверяются кривая,
бонусы без двойного усиления, бюджет, потери и 5000 составов с фиксированным seed.
`php tests/FleetExperiencePersistenceTest.php` проверяет реальные Fleet/MoveShip
и repositories через in-memory Table: dirty markers, сохранение/повторное чтение
runtime rows, переносы и расформирование. Это не MySQL flush/restart и не бой.

Прототип: `docs/balance/check_fleet_experience.py`.
Запуск из /opt/sp-game: `PYTHONDONTWRITEBYTECODE=1 python3 docs/balance/check_fleet_experience.py`.
Нужны Python 3 и доступ к работающему контейнеру swoole_app. Прототип выполняет
только SELECT игровых характеристик Vars, без доступа к данным аккаунтов.

Проверено 22 условия, включая 5000 составов с фиксированным seed: ограниченность
награды и бонусов, бюджет опыта, пропорциональное списание, переносы,
разбавление новичками, запрет посмертного перераспределения и предел опыта.
Это не тест production начисления и не имитация работы сервера/клиента.
Для случайных составов доли урона в прототипе моделируются долями атаки;
полный учёт урона/скорострельности предстоит проверить в боевом калькуляторе.

Примеры для одинаковых новых лёгких истребителей без технологий, когда
противник полностью уничтожен и атакующие сохранились:

| Численное превосходство | Опыт на выживший корабль |
| ---: | ---: |
| 1:1 | 20 |
| 2:1 | 2,5 |
| 3:1 | 0,740741 |
| 10:1 | 0,02 |

Это условные входные исходы для формулы награды, не утверждение, что бой 1:1
закончится победой без потерь. Уничтожение 100 малых транспортов сотней лёгких
истребителей при тех же допущениях даёт 2 очка; 100 безоружных зондов — 0.

При условных 10 очках на бой достижение e=150 занимает 15 боёв, e=1000 — 100.
Реальная скорость прокачки зависит от составов, потерь, технологий и доступных
целей; её необходимо измерить после подключения ATTACK.

До объявления баланса устойчивым нужны боевые серии: равные/контрсоставы,
разные технологии, несколько обороняющихся флотов, планетарная оборона,
большие транспорты/переработчики/звёзды смерти, повторные нападения,
потеря вместимости/топлива, failure injection и повторная обработка команды.
