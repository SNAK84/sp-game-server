## B032: финальное сохранение при штатной остановке

Причина установлена в текущем коде: в WSocket был saveAll только по
30-секундному таймеру, но не при завершении сервера. Принятый и уже
исполненный SendMission жил в Tables до очередного saver.

Добавлен синхронный Shutdown handler. В установленном Swoole5.1.6 этот
callback вызывается с выключенным coroutine-режимом; штатный shutdown
очищает таймеры и завершает workers до финального handler. Сверены точные
исходники [PHP callback](https://github.com/swoole/swoole-src/blob/v5.1.6/ext-src/swoole_server.cc#L1445)
и [порядок остановки](https://github.com/swoole/swoole-src/blob/v5.1.6/src/server/master.cc#L889).
В callback нет новых сетевых push/таймеров или задач боевым workers.

Существующий RepositorySaver в strict-режиме сначала восстанавливает pending
mining journal через обычный барьер, сохраняет dirty Fleet-кэш и все
зарегистрированные repositories. Проверяет getPendingSync после каждого
syncToDatabase: тот может поймать SQL-ошибку сам, оставив marker. Ошибки не
останавливают попытку сохранить остальные repositories, но запрещают
успешный финальный marker; WSocket передаёт ошибку main после выхода start.
Обычный периодический вызов saveAll() сохраняет прежний контракт.

Manager stop/restart и будущий compose-stop получают60с до принудительного
завершения. Настройки времени не являются обещанием защиты от SIGKILL,
отказа MySQL или произвольного crash посреди межрепозиторного сохранения.

## B003: принятая команда исполняется после disconnect

EventLoop теперь объединяет online IDs и владельцев опубликованных ready=1
событий. Offline-аккаунт без очереди не добавляется в проход. Сначала
согласуется игровое состояние, затем работает прежний processPlayerEvents;
проверки владельца/боя/лимитов/приоритетов не менялись. Push только online.

QA121 отправлен из SPA обычной OBSERVE к POINT4500/270°, бак100, груз0:

- ACK15:09:30.638, сокет закрыт15:09:30.639. Автопереподключение тестового
  браузера отключено; его собственная Selenium-сессия закрыта.
- ProcessPlayerEvents ActionFleetSendMission15:09:31.492 — уже ПОСЛЕ Close.
  Queue0, число авторизованных уменьшилось. До15:11 не было повторного
  входа QA10; SQL сохранил MOVE417/бак97 без участия клиента.
- Поздний login увидел уже выполняющийся рейс, не запустил вторую LOAD.
  Затем действующими SetFleetCommands(return) и ResumeFleet построен возврат.
  Прямой отзыв активного OBSERVE/P001 не менялся.

Три чистые проверки playerAccountIds покрывают дедупликацию online/offline,
неопубликованные события/невалидный ID и offline без очереди. Вместе с
предыдущим baseline CoreContracts173/0. Главные доказательства — основной
сервер и публичные запросы выше, не отдельные игровые Tables.
