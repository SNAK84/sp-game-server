# Дружба и заявки из галактики

## Что использовано из предыдущих движков

В Nova (`/opt/nova.snak84.ru/includes/pages/game/ShowBuddyListPage.class.php`
и `styles/templates/game/page.galaxy.ajax.tpl`) кнопка галактики открывает форму
для уже выбранного игрока: имя/координаты, текст, отправка. Список разделён на
входящие, исходящие и подтверждённых друзей. При заявке и ответе приходят сообщения.

В старом SP-Game (`/var/www/sp-game.ru/uni1_/includes/pages/ShowBuddyPage.php`
и `includes/classes/class.GalaxyRows.php`) такой же вход есть из галактики,
хранятся текст заявки, направление связи и отдельный признак принятия.
Старые SQL/GET-обработчики и их проверки прав не переносились.

## Текущий пользовательский сценарий

1. Кликнуть чужую планету в галактике.
2. В «Действиях с игроком» выбрать «Предложить дружбу».
3. В диалоге имя и координаты уже заполнены. Можно оставить текст до 500 Unicode-символов.
4. После ответа сервера видно подтверждение отправки. Страница остаётся галактикой.
5. В карточке отображается «Заявка отправлена», «Входящая заявка» или «У вас в друзьях».
   Эти кнопки ведут в управление заявками/друзьями, не создают повторную заявку.

В разделе «Друзья» убран ручной ввод ID. Входящие/исходящие показывают имя, координаты,
дату и текст. Координаты открывают нужную систему. У подтверждённых друзей есть
доступный серверу статус активности; отсутствие времени отображается как неизвестная
активность, а не как выдуманный online/offline.

Удаление подтверждённого друга требует подтверждения с предупреждением о влиянии
на миссию «Оборона». Заявку принимает только адресат. Отменять/отклонять могут
только участники; повторное удаление не создаёт новые уведомления.

## Контракт и сохранение

- Существующий `mode=friends`, действия `request`, `accept`, `remove` сохранены.
- Для `request`: `data.id` — ID адресата, опциональное `data.text` — обычный текст.
- Для остальных действий `data.id` — ID связи. Эти числовые ID остаются внутренними.
- Общий WS response/requestId pipeline не менялся. Действия `friends` в `Connect`
  не переключают `Account.mode`: получатель последующих `ActualData` остаётся текущим.
  Обычное открытие списка друзей продолжает менять страницу штатным способом.
- В Galaxy snapshot добавлены `Friendship: {state, id?}` для пары viewer/owner
  и `FriendRequestMaxLength`; чужие тексты/списки друзей не раскрываются.
- Текст хранится в единственной дополнительной колонке `friends.request_text`.
  Штатный `Friends::init` добавляет её, существующие строки получают пустой текст.
  Тип `VARBINARY(2048)` сохраняет UTF-8 байты, включая emoji, без изменения общего
  старого `utf8mb3` подключения MySQL. Runtime — Swoole Table, сохранение — RepositorySaver.
- Уведомления request/accepted/rejected/cancelled/removed идут через обычные
  `Notification::sendSystem → Messages → PlayerQueue → ActualData` в категории «Игроки».
- Клиент вставляет текст как текст, не HTML. Лимит и UTF-8 проверяет также сервер.

## Границы этапа

Не добавлялись альянсы, личная переписка и общий антиспам/cooldown. Производство,
ресурсы и исполнение миссий не переписывались.

При стресс-клике Messages → Friends до завершения fadeIn один раз потерялся
переход; повторный штатный клик работает. Это общий lifecycle/ordering навигации,
не новый механизм дружбы. Общий Router/BasePage здесь не изменялся. Для новых
кнопок перехода используется существующая последовательность hide → request → show.
