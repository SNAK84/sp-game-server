# Резерв топлива после боевых потерь — 19.10.2026

## Подтверждённая ошибка

Флот №21: 10 лёгких истребителей, максимум preview 230, к началу боя осталось 119.
Уцелел один корабль: вместимость 500 → 50, топливо 119 → 11,9. Это правильная
доля топлива по нашей механике. Обратные участки стоили 3, 7 и 4; на последний
осталось 1,9 вместо 4. Ошибка воспроизведена на отдельных Tables с копией реальных данных.

Расход `round(consumption) + 1` считается для каждого MOVE. После потерь он не
масштабируется линейно по числу кораблей. Кроме того, у смешанного остатка может
исчезнуть самый медленный корабль и измениться соотношение скоростей в формуле.

## Исправление

Для ATTACK / GROUP_ATTACK / DESTROY / DEFEND:

1. Верхняя оценка топлива до цели считается прежним способом.
2. Для каждого текущего типа считается обратный маршрут **одного** корабля,
   включая округление каждого MOVE и его собственную скорость.
3. Максимальное отношение «топливо возврата / вместимость корабля» умножается
   на полную вместимость исходного флота.
4. Новый максимум = верхняя оценка пути туда + этот резерв возврата.

После потерь сохраняется та же доля резерва, что и вместимости. В результате он
покрывает любую уцелевшую комбинацию текущих типов на предусмотренном обратном
маршруте. Цикла по каждому отдельному кораблю нет: стоимость вычисляется по типам.
Для исходного состава №21 preview теперь даёт min=228, max=255 вместо max=230.

Основная формула расхода, минимальный запас, пропорциональная потеря топлива,
время/скорость полёта и прочие миссии не менялись. В activateNextCommand добавлен
допуск 0,000001 для погрешности DOUBLE/сохранения дробной доли; отрицательный
остаток в пределах допуска превращается в ноль. Настоящий дефицит по-прежнему
отклоняется, а не компенсируется бесплатным топливом.

## Границы и оставшиеся риски

- Минимальный запас не обещает безопасный возврат после потерь; гарантированный
  резерв может быть особенно консервативным у сильно смешанного состава.
- Оценка действует для текущих характеристик/типов и существующего маршрута.
  Изменение характеристик во время полёта или будущий редактор маршрутов требуют
  отдельной политики пересчёта топлива.
- Общий scheduler по-прежнему останавливает цикл при другой неразрешённой ошибке
  команды. Пропускать раннее событие без анализа хронологии боёв/ресурсов здесь
  не стали: полноценная изоляция blocked fleet требует отдельного этапа.
- Постоянная надёжная доставка PlayerQueue не реализовывалась; разовый импорт
  при этом ремонте не исправляет C4 и не является новым production-механизмом.
