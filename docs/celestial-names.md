# Названия небесных объектов

Реализовано 25.10.2026 для текущего backend `/opt/sp-game` и SPA `/var/www/spa.snak84.ru`.
Исторические версии не изменялись. Предшествующие незакоммиченные изменения сохранены.

## Аудит и точки интеграции

В текущей модели одна строка `Galaxy` описывает систему и единственную звезду.
Двумерная геометрия принадлежит системам; планеты, луны и ресурсные объекты
сохраняют прежние идентификаторы, номера орбит и физические привязки.

`Galaxy::getSystem()` лениво вызывает `GalaxyGenerator::generateSystem()`.
Имя теперь записывается при этом создании. `generatePlanet()` и расчёт
звёзд, расстояний, распределения орбит и ресурсов не менялись.

`CreatePlanet()` вызывается из `AccountData` и `Planets::findByUser()` для
стартовой планеты. Оба вызова теперь передают `null` вместо `HomeworldName`.
Фактическая колонизация создаёт строку отдельно в `FleetColonizationService`;
изменено только присвоение имени и признака его происхождения.
Луны по-прежнему подготавливает `MoonFormationService::prepare()`, а применяет
существующий commit ATTACK. Новый механизм создания луны не добавлялся.

При запуске Planets загружается раньше Galaxy, затем GalaxyOrbits и ресурсные
репозитории. Штатный `BaseRepository::init()` добавляет отсутствующие SQL-колонки
и загружает данные в Swoole. Runtime остаётся источником истины; RepositorySaver
сохраняет изменения в MySQL. Фактический интервал saver — 30 секунд.

## Алгоритм

`CelestialNameGenerator` работает только со строками. SQL, репозитории,
владение, геометрия и физические характеристики ему неизвестны.

Система: `(galaxy, system, seed)` задаёт перестановку каталога размером 32768.
Нечётный множитель и смещение из SHA256 образуют биекцию по модулю 32768.
Код разбивается на префикс из двух латинских букв, корень из двух букв и
окончание переменной длины. Выбираются допустимые порядковые сегменты, а не
готовые имена. Фиксированные границы первых двух частей и уникальные окончания
исключают коллизии. Для следующих блоков идентификаторов добавляется устойчивый
каталоговый суффикс в base36. Он сохраняется буквально в обоих языках.
Полный перебор существующих систем, SQL-поиск имени и отдельный индекс не нужны.
Порядок создания систем не влияет на результат.

Планета: SHA256 от версии seed, галактики, системы, орбиты и номера попытки
выбирает фонетическое семейство, префикс, необязательный связующий слог, корень
и окончание. Семейства дают мягкое, классическое фантастическое и более
необычное звучание. У лун собственные семейства и дополнительный номер спутника.
Сейчас модель допускает одну луну на планетной орбите, поэтому используется
номер спутника 1. Глобальные `rand`/MT и поток физической генерации не затрагиваются.

Общая проверка отбрасывает три согласных/гласных подряд, повторяющиеся слоги,
монотонные повторения согласных и нежелательные сочетания, включая границы
слогов. Занятые имена проверяются только через индекс планет одной системы;
сравнение учитывает регистр и русский вариант ручного имени. После 96 попыток
используется ограниченная каталоговая ветка `Lira-...`/`Luna-...`.
Существующие имена никогда не заменяются ради устранения совпадений.

Единственная звезда носит имя системы. Метод для обозначений A/B/C доступен
только при явном номере компонента; дополнительных звёзд он не создаёт.
Газовый гигант получает имя звезды и римский **реальный номер орбиты**.
Пояса нумеруются I, II, ... по возрастанию сохранённых номеров их орбит.
Имена гигантов, поясов и их секторов собираются только в представлении.
Колонка `GalaxyOrbits.name` не добавлялась.

## Хранение, локализация и переименование

Добавлены штатными декларациями репозиториев:

| Поле | MySQL | Swoole | Назначение |
| --- | --- | --- | --- |
| `galaxy.name` | `VARCHAR(32) NOT NULL DEFAULT ''` | STRING, 32 байта | Каноническое имя системы |
| `planets.name_generated` | `TINYINT UNSIGNED NOT NULL DEFAULT 0` | INT, 1 байт | Отличает автоматическое имя от ручного |

`planets.name` остаётся прежним STRING(32)/VARCHAR(32).
Генерируемое имя хранится в латинице один раз. Русское представление получается
детерминированной транслитерацией: Velaria → Велария, Nirella → Нирелла,
Altaris → Альтарис. Язык берётся из `Account.lang`; независимых случайных
названий для разных языков нет. Существующий Lang не расширяется тяжёлым словарём.

`CreatePlanet(int $userId, ?string $NamePlanet = null, bool $HomeWorld = false,
?array $position = null)` сохраняет прежние позиционные и именованные вызовы.
`null`, пустая или пробельная строка включают автоматическое имя.
Непустое явное имя сохраняется буквально. Некорректный UTF-8 или имя длиннее
32 байт отклоняются до генерации, чтобы Swoole не обрезал строку.
Ручное переименование сохраняет прежний диапазон 2–20 символов и дополнительно
проверяет 32 байта; обработчик очереди снимает `name_generated`.

Карта, обзор, список планет, справка и новые уведомления показывают имя по
языку получателя. Платный снимок фаланги фиксирует имя при создании; повтор
не меняет снимок. Новые боевые архивы хранят каноническое имя и признак
генерации; чтение локализует копию. Игроки и имена флотов не транслитерируются.
Исторические сообщения/архивы без признака происхождения остаются буквальными.

Старые системы заполняет `Galaxy::ensureNames()` после загрузки, до запуска
игровых обработчиков. Он меняет только пустое имя, без вызова физического
генератора. Пакеты по 256 сохраняются штатным saver, затем освобождаются
только подтверждённые маркеры этого пакета: общий syncTable имеет ёмкость 2048.
Ошибка SQL прерывает запуск; безопасный повтор выполняется после новой загрузки.
Разрушительных миграций и отдельного SQL-скрипта нет.

без сохранения массива результатов и без запросов SQL:

| Планеты | 198,40 мс | 880,20 мс |
| Луны | 182,54 мс | 1117,29 мс |

Это разовые измерения на работающем dev-сервере; время зависит от нагрузки
и отладчика. Конфигурация основного сервера ради замера не менялась.
Генерация производится при создании, а не при чтении сохранённого объекта.

При Table(16384) фактическая дельта выделенных mappings `/proc/self/maps`:
Galaxy.name — 708608 байт, флаг Planets — 155648 байт, всего **864256 байт
(844 КиБ)** shared memory. Размеры таблиц и индексы не увеличивались.
Загрузка класса сервиса в отдельном PHP-процессе — около 78,5 КиБ;
добавочный пик одной генерации системы — около 760 байт.
Счётчик `getMemorySize()` даёт меньшую дельту и не использован как полная оценка.

Проверка рабочего сервера после штатного перезапуска: 20 систем имеют 20
уникальных непустых сохранённых имён; все имена 34 прежних планет/лун и
физические поля систем сохранены. Их флаги остаются 0. Новые игровые планеты
ради проверки не создавались. Свежие startup-логи подтверждают запуск WebSocket
и игровых таймеров; повторная загрузка имён дополнительно проверена изолированным SQL-тестом.

## Ограничения

- Фонетическое качество субъективно. Выборка 100/100/50 просмотрена; фильтр
  не является полным словарём всех нежелательных сочетаний во всех языках.
- Уникальность систем гарантируется для одинакового seed в пределах одной
  галактики. Нельзя менять версию алгоритма/seed для уже используемой галактики
  без проверки совместимости новых имён с сохранёнными.
- Планетные и лунные имена могут повторяться в разных системах. Внутри системы
  новые имена избегают уже занятых; ручные дубли не запрещаются.
- Номер пояса устойчив при загрузке неизменных сохранённых орбит. Если будущая
  механика начнёт вставлять/удалять пояса, понадобится отдельное решение для
  неизменных порядковых номеров. Сейчас такой механики нет.
- Настройка регионального звучания возможна через стабильный seed; отдельные
  поля региона и multi-star модель не добавлялись.
- Существующий 32-байтовый лимит ручного имени сохранён и теперь проверяется
  явно. Старые названия не переименовываются и автоматически не переводятся.
- Chromium проверял изолированный DOM текущего клиента. Полный авторизованный
  пользовательский сценарий создания объекта в живой игре не выполнялся.
- В общем diff SPA есть предшествующий whitespace в `js/tooltip.js`; файл этой
  задачей не изменялся. Целевой `GalaxyPageClass.js` проходит diff check.
