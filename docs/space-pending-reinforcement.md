# B031: позднее подкрепление обычного перехвата

Исправлено01.11.2026 на основном dev. Клиент и протокол не менялись.

## Причина и исправление

1. Первый раунд уже dispatch-нут в TaskWorker.
2. Во время расчёта arrives обычная ATTACK другого флота. reinforceAt добавляет
   участника в pending на раунд2 и замораживает ATTACK через battleWait.
3. Раунд1 заканчивает бой. Подкрепления нет в result groups и counts: оно
   действительно не стреляло, не получало урон и не заработало XP.
4. Раньше prepareResult удалял battleWait, но оставлял ATTACK unexecuted с
   pause=battle. resume пропускал её из-за отсутствия флота в engaged.
   У атакующего не запускался возврат; защитник мог повторно пытаться выполнить
   уже закончившуюся атаку вместо продолжения своего следующего участка.

Для обычного пространства (не resourceSite) result-plan теперь завершает эту
ATTACK и обновляет время позиции. Состав, XP, груз и топливо боя не меняются;
проверка неизменности замороженного груза/топлива сохранена. Поздний участник
не становится engaged, не включается в распределение добычи или награды.

Отдельный resolution.spaceWaiting записывается тем же SpaceBattles checkpoint.
Существующий resume включает таких атакующих в запуск оставшегося маршрута.
Защитник остаётся на pause=battle первой следующей команды; при отсутствии
маршрута создаётся прежний paused OBSERVE. Этот небольшой блок вынесен в
общий pauseDefenderRoute и используется также для реально участвовавших
защитников. Правила ресурсного боя/resourceWaiting и B030 не расширялись.

возобновления worker считает настоящий первый раунд обычным калькулятором.

## Проверки и границы

PHP lint обоих PHP-файлов, Python py_compile, own diff и git diff --check.
Live runner проверяет admissions/раунды до удаления checkpoint; последующие
SQL-проверки используют готовый доклад и реальные строки флотов/команд.
Чтение до cleanup и после него — разные стадии, отсутствие applied checkpoint
не считается провалом или отсутствием боя. QA-проверки привязаны к этой сцене,
а не к вечной неизменности ID/маршрута после действий игрока.

Restart проверен после сохранённого результата, а не авария между всеми
строками application plan. Не заявляется проверка B032 (быстрый stop до saver).
Финально8 WS-страниц overview/buildings/researchs/shipyard/defense/fleets/galaxy/
messages ответили status=ok; обычное чтение вернуло ActualData-подписку браузеру.
Main Running=true, OOMKilled=false; после последнего запуска ERROR/CRITICAL/
WARNING0. Своя Selenium-сессия закрыта, сервер оставлен работать.
Следующий баг рассматривается отдельно; исторические ошибки подготовки
в логах не выдаются за ошибки текущего запуска.
