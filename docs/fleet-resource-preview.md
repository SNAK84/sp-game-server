# B011 — неполная ресурсная цель в preview маршрута

29.10.2026. Production-правка только в SPA FleetsPageClass.js. Backend,
WebSocket-протокол, обязательность siteId и сохранённые маршруты не менялись.
Перезапуск игрового сервера для этой правки не требовался.

## Причина и воспроизведение

Настоящий QA37, обычный редактор с возвратом:

1. Система1:6 возвращает resourceSites=[]. Нажат «Пояс».
2. Пустой select даёт Number(null)=0. Прежний validCoordinates пропускал
   OBJECT по галактике/системе/орбите, не проверяя ресурсный siteId.
3. Отправлялся не только preview самого этапа с coordinates.siteId=0,
   но и возврат с origin.siteId=0. Coordinate::fromArray(origin) отвергал
   некорректный объект; сервер возвращал Server error.
4. Дополнительный реальный UI-lifecycle: после выбора сектора18 в1:7 введена
   система6 только событием input, до change/blur. Отправлялся старый siteId18
   уже с system6 — положительный ID сам по себе не означает готовую цель.

## Исправление

- Для GAS_GIANT/ASTEROID_SECTOR preview требует целый siteId>0 у цели и origin.
- При сборке координаты выбранная option сверяется по galaxy/system/orbit/
  objectType/siteId. Несоответствие помечает координату незавершённой; такой
  payload не отправляется. Чужой сектор не подставляется вместо отсутствующего.
- Origin выводится из последнего предыдущего координатного этапа, как раньше.
  Теперь его pending/navigationError также блокируют зависимый preview и входят
  в ключ запроса: завершение загрузки автоматически возобновляет проверку.
- Изменён только расчёт/проверка состояния диалога. Пересоздания DOM нет.

## Отдельная находка

B041: после invalid NavigationSystem/onError row.pending снимается без refresh,
поэтому aria-busy и fuel notice могут остаться в ожидании при pending WS=0.
Это существовавшая ветка, не изменённая B011. Тест здесь подтверждает запрет
неполного preview/submit и последующее восстановление, но не объявляет
исправленным индикатор invalid navigation. Находка записана в found-bugs.md.
Первый расширенный прогон остановился на этом ожидании; после фиксации B041
проверка B011 ждёт завершения WS-запроса и проверяет запрет отправки, а не
считает снятым зависший визуальный aria-busy.
